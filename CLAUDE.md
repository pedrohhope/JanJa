# CLAUDE.md

Guia para quem (humano ou IA) for mexer no JanJa. Leia antes de mudar código.

## O que é

Site para amigos compartilharem tela, voz e câmera e jogarem poker, truco, sinuca, Stop, batalha naval, Mistério, mini-golfe, xadrez, damas, Velha ao quadrado, pife, Magnata um tiroteio pixel (Tiro na Sala) e uma luta de plataforma (Briga na Sala) juntos, direto do navegador. React 19 + Vite + TypeScript estrito no front; Cloudflare Worker com um Durable Object por sala (`Room`, Hibernation API, SQLite) no back. A mídia vai P2P em mesh WebRTC; o servidor só faz sinalização e roda os jogos. Há também o **JanJa Helper** (`helper/`, Rust, Windows) para controle remoto.

Produção: https://janja.spotlightre.workers.dev (deploy automático da Cloudflare a cada push na `main`).

## Comandos

```bash
npm run dev               # build + wrangler dev em http://localhost:8787
npx vite                  # só o front (rotas de laboratório /dev/poker, /dev/golf e /dev/audio)
npm run typecheck         # 3 tsconfigs: web, worker, testes
npm test                  # vitest (ambiente node)
npm run test:e2e          # Chrome de verdade contra o wrangler dev
npm run sprites           # regenera public/game/sprites.{png,json} a partir de src/web/game/art
npm run thumbs            # refaz os prints da vitrine de jogos (public/game/thumbs/*.webp) a partir dos laboratórios /dev/* e reescreve src/web/ui/games/thumbs.ts
npm run icons             # regenera public/icons/icon-{192,512}.png (TV) e public/favicon.svg (Jan fazendo o L) a partir de src/web/ui/pixelData.ts
npm run validate-commits  # confere a mensagem do último commit
cd helper && cargo test   # helper (em Linux a injeção de input é um stub)
```

Antes de entregar qualquer mudança: `npm run typecheck && npm test && npx vite build`.

## Regras de produto e de texto

- Todo texto de interface em **português do Brasil**, frases curtas e simples. Sem CAIXA ALTA, sem setas "→", sem jargão.
- Visual "a TV da sala": fundo café `#221C19`, abajur `#FFC94A`, papel `#F3EBDD`, poeira `#B7A99A`; fontes Archivo (interface) e Pixelify Sans (pixel). Tokens em `src/web/styles.css` (`:root`). Nada de gradiente chamativo nem cara de template.
- Pixel art é sempre gerada por código (`src/web/game/art`, `src/web/ui/pixelData.ts`). Não adicione imagens prontas. A exceção são os prints da vitrine de jogos (`public/game/thumbs/`): são gerados pelo `npm run thumbs` a partir dos laboratórios `/dev/*` e versionados; rode de novo quando o visual de um jogo mudar.
- Dica de botão em jogo usa `useInputDevice` (`src/web/game/useInputDevice.ts`) + `<Glyph>`/`<Key>` (`src/web/ui/InputGlyph.tsx`), que trocam teclado, controle (Xbox, PlayStation, Nintendo) e toque sozinhos; no navegador do dev, `?pad=xbox|playstation` força o controle. Sem vibração (decisão do dono: não use `vibrationActuator`).
- Mic começa **mudo** e a câmera começa **desligada**. Escolhas da pessoa vão para `storage.ts`.
- Erros para a pessoa dizem o que fazer ("Libere no cadeado da barra de endereço"), nunca só o nome técnico.

## Restrições técnicas que já morderam

- **CSP** em `public/_headers`: sem `eval`, sem worker de `blob:`, conexões só para `'self'`, `wss:` e `ws://127.0.0.1:47800` (helper). Por isso:
  - o Pixi importa `pixi.js/unsafe-eval` primeiro e usa `Assets.setPreferences({ preferWorkers: false })`;
  - qualquer lib nova precisa funcionar com essa CSP (teste no build servido pelo wrangler, não só no `vite`).
- **Deploy com a aba aberta.** Cada deploy apaga os pedaços (chunks) antigos e o `not_found_handling` devolve o index.html no lugar, então um `import()` da versão velha falha. Componente carregado sob demanda usa `lazyChunk` e import solto usa `loadChunk` (`src/web/version.ts`): falhou, a página recarrega uma vez sozinha. O `watchVersion` avisa na sala quando sai versão nova, e o `ErrorBoundary` em `main.tsx` mostra "Recarregar" em vez de página branca.
- **Pixi só no chunk da mesa; Three só no do golfe, no do xadrez 3D e no do tiro 3D.** Os tabuleiros do xadrez, das damas e do Magnata são HTML/SVG puro, sem biblioteca, e também carrega por `import()`. As cenas e o áudio carregam por `import()` em `src/web/game/loaders.ts`. Não importe `pixi.js` nem `gsap` fora de `src/web/game/scene`, `src/web/game/shooter/scene`, `src/web/game/brawl/scene` e `audio`, nem `three` fora de `src/web/game/golf/scene`, de `engine.ts`/`real.ts` em `src/web/game/chess/scene3d/` e de `engine.ts` em `src/web/game/shooter/scene3d/` (carregado por `loadShooter3DScene`; os outros arquivos de `scene3d` são puros ou só canvas) (só carregam quando a pessoa escolhe 3D ou Real, por `loadChunk`; `voxels.ts`, `lathe.ts` e `wood.ts` são puros).
- **Tela x câmera x mic no receptor** são separados pelo `PeerState`: `screenStreamId` e `camStreamId`. Publique o estado **antes** de adicionar a trilha (`publishState` e depois `manager.startX`), senão o vídeo chega sem classificação.
- **Jogos são puros.** Motor recebe `GameCtx { now, rng }`; nunca use `Date.now()` ou `Math.random()` dentro de `src/shared/games`. Cada conexão recebe só a própria `view`: nunca coloque cartas de outra pessoa na visão fora do showdown.
- **Golfe é simultâneo e determinístico.** O jogo tem `concurrent: true`: o `GameHost` aceita `seq` antigo e o motor recusa tacada repetida pelo `stroke`. A física (`physics.ts`) roda igual no Worker e no navegador: passo fixo de `STEP_MS`, e dentro do laço só `+ - * / sqrt` (nada de `Math.sin`, `Math.hypot`, `Math.random`). O estado guarda um retrato do mundo (`t0` + bolas) e o alarme acorda no próximo instante em que alguma bola muda de estado (`nextChange`). Mapa novo: arquivo em `src/shared/games/golf/maps/` (legenda no topo de `course.ts`), 6 a 12 buracos; o teste `tests/golf/maps.test.ts` confere que dá para chegar no buraco.
- **O tiro é o único jogo em tempo real e não roda no servidor.** O Durable Object só coordena (`engine.ts`: quem é o host da simulação, `epoch`, placar, resultado e prazo de segurança). A simulação roda no navegador do host (`net/hostWorker.ts`, Web Worker de módulo: a CSP não aceita worker de `blob:`), a 40 Hz; entradas e snapshots vão pelo canal negociado "game" (id 8, sem ordem e sem retransmissão) e, sem P2P com o host (outro canal de voz, NAT), pelo repasse `game-relay` do servidor (só repassa, limite `RELAY_MAX_PER_SEC`). Se o host sai, o coordenador escolhe outro, sobe o `epoch` e o novo host continua do último snapshot. Dá para entrar no meio (`addPlayer` no `GameDefinition`). `movePlayer` é a mesma função no host e na predição do cliente. A pistola tem `ammo: Infinity`: estado que passar por JSON precisa de `reviveState`. Laboratório: `/dev/shooter?map=quintal&bots=3` (`window.__tiro`); `?view=3d` abre em primeira pessoa, `?view=2d` de cima.
- **Briga na Sala usa a plataforma `realtime/`, como o tiro, mas a 60 Hz.** A simulação (`sim.ts`) é determinística (sem `Date.now`/`Math.random`; sorteios por `rng.ts`) e roda no navegador do host; o Durable Object só coordena (escolha dos personagens, pronto, placar, resultado, revanche). `predictSelf` mexe só no próprio lutador e **não avança `state.tick`** (o binding ajusta `tick - 1` antes de cada chamada); o cliente aplica `quantizeInput` para a predição bater com o host. A cena fica em `src/web/game/brawl/scene` (Pixi só no chunk de `loadBrawlScene`); HUD e retratos usam módulos puros. Laboratório: `/dev/briga?arena=telhado&bots=3&char=janja&nivel=dificil&modo=tempo` (`window.__briga`: `state`, `ko(slot)`, `give(slot, arma)`, `damage(slot, n)`; tecla de depuração mostra caixas de golpe e fps).
- **Xadrez, damas e Velha ao quadrado são de duas pessoas, uma de cada vez**, e dividem relógio, empate, desistência e abandono em `duel.ts` (jogo novo assim: reuse em vez de copiar).
- **Xadrez.** Cores sorteadas no `setup` (`ctx.rng`). O relógio desconta na hora do lance (`turnStart` + `clock`) e o alarme acorda quando o tempo de quem joga acaba; lance que chega depois disso vira derrota por tempo. Quem sai da sala perde depois de `ABANDON_MS`. Fim automático: mate, afogado, repetição tripla, 50 lances e material insuficiente. O teste `tests/chess/rules.test.ts` confere o gerador de lances com perft; mexeu em `rules.ts`, rode ele.
- **Velha ao quadrado.** 9 tabuleiros pequenos dentro de um grande; X começa (X é o lado `w` do duelo, sorteado). A casa em que você joga manda o outro para o tabuleiro de mesmo número (`forced`); se ele já fechou (ganho ou cheio), o outro joga em qualquer aberto. Tabuleiro pequeno cheio sem linha vira `'empate'` e não conta para ninguém. Vence quem fizer três tabuleiros em linha no grande; sem linha possível para os dois (ou sem lance), é empate (`velha`), sem contar quem ganhou mais. Relógio, empate, desistência e abandono vêm do `duel.ts`. Mexeu nas regras, rode `tests/velha/` (inclui partidas aleatórias inteiras).
- **Pife é rodada avulsa: quem bate ganha.** 2 a 8 pessoas, dois baralhos com os 4 coringas (108 cartas, id `Ah.1`, `10s.2`, `JK.3`), 9 cartas cada. Na vez: compra do monte ou pega a de cima do lixo, depois descarta ou bate. Não devolve ao lixo a carta que acabou de pegar dele. Jogos de 3 ou mais: trinca do mesmo valor de qualquer naipe (sem coringa) ou sequência do mesmo naipe (ás antes do 2 ou depois do K, sem dar a volta; o coringa só entra em sequência e ela precisa de uma carta de verdade). Bater: todas as cartas em jogos, descartando uma ou não (`findWin`). Monte acabou: o lixo, menos a de cima, vira monte. Cada um vê só a própria mão; no fim todo mundo vê tudo. A ordem da mão é só da tela (arrastar e Organizar). Mexeu nas regras, rode `tests/pife/` (inclui partidas inteiras de bots com 2 a 8).
- **Damas são as brasileiras.** Pedra captura para trás, dama voadora, captura obrigatória com lei da maioria, peças capturadas só saem no fim do lance (não dá para pular duas vezes) e a pedra só vira dama se terminar na última fileira. O lance é o caminho inteiro (`path`), porque com dama mais de um caminho pode chegar na mesma casa. Empate: repetição tripla ou 20 lances de cada lado só com damas e sem captura.
- **Truco é o gaudério, do jeito da nossa mesa.** Baralho espanhol de 40 com manilhas fixas, partida até 30, envido (envido/real/falta, e a falta vale o que falta para o líder chegar a 30), "o envido está primeiro", flor obrigatória (o jogo canta sozinho, vale 3) e contra-flor (6), sem "ao resto". Times pela cadeira (pares x ímpares); quem dá as cartas é sorteado e a vez anda no sentido anti-horário (índice seguinte). 1x1, 2x2 e 3x3; no 3x3, entre 5 e 25 pontos dos dois times, alterna mão normal com mão de "testa" (três duelos 1x1 simultâneos contra quem está na frente). Por causa da testa o jogo é `concurrent` e toda ação leva o `ref` da mesa. Cartas dos outros nunca vão na visão. As cadeiras exatas vêm de `GameDefinition.seats(options)`. Mexeu no motor, rode `tests/truco/property.test.ts`.
- **Batalha naval**: 1x1, mar 10x10, frota de 5 (porta-aviões 5, encouraçado 4, cruzador 3, submarino 3, destróier 2), navios não encostam nem na diagonal. Os dois posicionam ao mesmo tempo (o jogo é `concurrent`; o tiro leva o `ref` = tiros já dados). Modo clássico (um tiro; acertou, joga de novo) ou salva (um tiro por navio de pé, numa rajada). A frota do outro nunca vai na visão: só tiros e navios afundados; no fim mostra as duas. Prazo: posiciona sozinho em `PLACE_MS` e atira sozinho em `SHOT_MS`.
- **Sinuca (bola 8) é física determinística, como o golfe.** Passo fixo (`HZ`) e só `+ - * / sqrt` no laço; a tacada chega como vetor (sem seno/cosseno). O servidor simula a tacada inteira de uma vez e guarda o "antes" (`shot.before`); o navegador anima a mesma simulação e, no fim, encaixa nas posições do servidor. Regras: mesa aberta depois da quebra, grupo definido pela primeira bola encaçapada sem falta, faltas (branca na caçapa, não tocar, tocar primeiro na bola errada, nenhuma bola na tabela depois do toque) dão bola na mão, e a 8 só vale na caçapa escolhida (`pocket`). A tacada leva o `ref` (tacadas já dadas) e o efeito (`spin`: lateral e alto/baixo); a bola desliza e depois rola (`rx`/`ry` só existem durante a simulação, `settle` tira antes de guardar). Força pelo arrasto (puxa o taco para trás). A mira ao vivo de quem joga vai pelo repasse `game-relay` com `to: '**'` (a sala toda, quem assiste também; `src/web/game/pool/aim.ts`) e não passa pelo motor. Mexeu na física, rode `tests/pool/` (inclui partidas inteiras aleatórias). Não use o nome nem o visual de "8 Ball Pool".
- **Stop é simultâneo e com respostas escondidas.** O jogo é `concurrent`; as ações levam o número da rodada. Enquanto escrevem, a visão só leva as suas respostas e quantas categorias cada um preencheu; as dos outros só depois do STOP. STOP só com tudo preenchido com a letra; depois tem `GRACE_MS` para as últimas respostas chegarem (a tela manda o que está escrito na hora). Conferência: "não vale" cai com a maioria dos outros; pontos 10 (única), 5 (repetida, comparando sem acento nem maiúscula), 0. Letras sem K, W, Y e sem repetir.
- **Mistério é nosso, não cópia.** Mecânica de dedução (palpite, alguém mostra uma carta em segredo, acusação), mas o tema (roubo do quadro no Casarão da Vila), suspeitos, lugares, objetos e arte são próprios: não use nomes, personagens, cômodos ou armas de Detetive/Clue. Tabuleiro com dados (`board.ts`: planta do Casarão em ASCII, cômodos, portas e `reachable`): todos começam no Saguão (moldura vazia; não é lugar de palpite); na vez rola dois dados e anda até a soma (entrar num cômodo gasta um passo e para; não volta para o cômodo de onde saiu na mesma vez; peões dividem casa). Parou no corredor ou no Saguão, a vez passa; entrou num lugar, palpita ali (o `onde` é o cômodo). Acusar vale de qualquer lugar, antes de rolar ou depois de entrar/palpitar. Quem mostra é o próximo da roda que tiver alguma; com uma só, o jogo mostra sozinho. A carta mostrada só vai na visão de quem palpitou e de quem mostrou. Errou a acusação: sai, vê a solução em segredo e continua mostrando cartas. O caderno (`notes.ts`) marca sozinho o que dá para deduzir pela visão; o resto fica no `localStorage`.
- **Magnata é nosso, não cópia.** Mecânica de jogo de imóveis, mas nome, tabuleiro (cidades brasileiras), cartas e arte são próprios: não use nomes, casas, cartas ou visual de Monopoly, Banco Imobiliário ou Business Tour. Para ser rápido: constrói na compra (até 3 casas; hotel quando cair de novo), pode comprar a cidade dos outros por 2x o investido (menos com hotel), vitória na hora com 3 grupos, um lado inteiro ou as 4 praias, e toda vez tem prazo (`ROLL_MS`/`DECIDE_MS`): estourou, o servidor rola ou passa por você. Dívida vende sozinha as cidades mais baratas pela metade. O teste `tests/tycoon/property.test.ts` joga partidas aleatórias inteiras conferindo as regras; mexeu no motor, rode ele.
- **Canais e limite.** A sala tem canais (padrão: só "Geral", sem limite) que o host cria, edita e apaga; **cada canal tem o seu limite** (`Channel.limit`, `0`/ausente = sem limite, escolhido ao criar e editável pelo lápis; baixar não tira ninguém), gravados no `RoomConfig`. Canal cheio recusa `channel-join` (`channel-full`); quem chega cai no primeiro canal com vaga, e se todos estiverem cheios não entra (o host entra). A sala em si não tem limite visível: só o teto de segurança `MAX_PEERS = 100`. A mídia continua P2P **dentro do canal**: o `useRoom` só chama `manager.addPeer` para quem está no mesmo canal e refaz as conexões no `peer-moved`. Acima de `HEAVY_CHANNEL` (8) pessoas num canal a malha pesa e a interface avisa. A **tela** pode ir pelo SFU (veja "Tela híbrida"); voz e câmera continuam na malha. O host sempre entra, mesmo com a sala cheia. Os jogos são da sala inteira (Stop aceita até 10; Velha ao quadrado, 2; pife, até 8; poker, golfe e tiro, até 8; briga, até 8; Magnata e Mistério, 6; truco, 2, 4 ou 6 exatos; xadrez, damas, batalha naval e sinuca, 2).
- **Nome da sala ("servidor").** Escolhido na Home ao criar (vazio = "Sala de <apelido>"), mostrado no topo da barra lateral (`ServerCard`) e no título da aba; só o dono troca (`room-rename`). Fica em `RoomConfig.name` e vai em `RoomSettings.name`; sala antiga sem nome usa `DEFAULT_ROOM_NAME`. "Outros servidores" lista as salas recentes pelo nome (`RecentRoom.name`).
- **Chat do canal** passa pelo servidor (`chat-send` / `chat` / `chat-history`), só para quem está no canal. O Durable Object guarda as últimas `CHAT_HISTORY` (50) por canal em `chat:<canal>`; apagar o canal apaga o chat; limite de 8 mensagens a cada 10 s por pessoa (`chat-flood`).

## Pegadinhas de UI conhecidas

- **Campo de texto livre leva `{...noAutofill('nome')}`** (`src/web/ui/noAutofill.ts`) e o `<form>` leva `autoComplete="off"`. Sem isso o Chrome oferece Google Pay ou cartão salvo no chat e nos nomes.
- **Não coloque o `Dropdown` dentro de `<label>`**: o clique na opção é repassado ao botão e a lista reabre. Use `<div>`.
- **Classes CSS curtas colidem.** `.cam` é o botão da barra; o quadro de câmera é `.cam-tile`. O estado do mic é `.is-muted`/`.is-live` (não `.muted`, que é texto apagado).
- Botões são estilizados por variáveis (`--bg`, `--bg-h`, `--bd`, `--bd-h`, `--fg`). Para um botão novo, troque as variáveis em vez de sobrescrever `background`, senão o hover quebra.
- Texto dentro do canvas do poker usa `PxText` em alta resolução (`TEXT_RES`); posições continuam em pixels da cena.
- A barra de baixo encolhe rótulos com `@container` antes de quebrar linha; botão novo na barra precisa caber em 1440 px com a barra lateral aberta.

## Tela híbrida (P2P + SFU)

- Só a tela (vídeo + áudio da tela) passa pelo SFU; mic, câmera e canais de dados (`game`, `control`) ficam na malha. Plano completo: doc `plano-tela-hibrida` do projeto.
- **O cliente nunca fala com a API do Realtime.** As mensagens `sfu-*` vão pelo WebSocket da sala; o `RoomCore` cria a sessão de cada pessoa, checa quem pode assinar (mesmo canal, `screenRoute: 'sfu'`, `screenStreamId` igual e push já feito) e chama a API. Toda mensagem com `requestId` recebe um `sfu-reply`.
- **Attachment do WebSocket tem 2 KB.** `ConnData.sfu` guarda o mínimo (assinatura = `{ mid, kind, from }`); o resto vem de quem publicou. Não aumente isso sem medir.
- **Troca monta antes de desmontar:** mesh→sfu publica, publica o estado, espera 6 s e só então tira a tela da malha (`setScreenMesh(false)`); quem assiste só troca o `<video>` depois do primeiro quadro (`firstFrame`). Qualquer falha volta para a malha e respeita `FAILURE_COOLDOWN_MS`.
- **Camadas:** `a` segue o nível de quem compartilha, `b` 720p30, `c` 360p30; quem assiste pede pela área do vídeo (`ridForSize`). Em `economia` ninguém recebe `a` (`allowedRid`).
- **Orçamento:** os clientes mandam `sfu-usage` (bytes recebidos do SFU) a cada 30 s; o DO `Budget` soma no mês e na sala/dia. É estimativa: confira no painel da Cloudflare de vez em quando.
- Sem os secrets `REALTIME_APP_ID`/`REALTIME_APP_SECRET`, `welcome.sfu.enabled` é `false` e nada disso liga.
